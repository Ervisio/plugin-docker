# Changes from the transfers branch (feat/transfers)

Needs Ervisio 0.5 (SDK 0.2). `package.json` now uses `@ervisio/plugin-sdk` from `github:Ervisio/plugin-sdk#release/0.2` (re-pin to the v0.2.0 tag at release).

- Downloads: the settings export, the template export and the container log now save through the browser (`saveFile`). Nothing is written to `~/.config/ervisio/plugins/docker/exports` or `/logs` any more, and the copy-only "exported file" window is gone from the settings export (the template export keeps its preview with Copy and Download).
- Container files: no more 760 KB or 8 MB limit. Upload any size (the file is never read into memory: the tar header is added around it). Download a file up to 64 MB under its own name, a bigger file or a folder as a `.tar`, streamed to disk. New "Download this folder" button and a "Download as .tar" button on every folder row. Upload shows progress and can be cancelled.
- Build image: the Upload source takes a context of any size. An archive is sent as it is; picked files and folders are packed without reading them into memory and compressed up to 64 MB. The build output is streamed back while the context goes out, with a progress bar for the upload. Git URL builds are unchanged. The limit text is gone.
- Images: Export one image (row action, also per tag), several (tick the rows, "Export selected") or all tags of one image from its details, saved as a `.tar` (`docker save`). Import a `.tar` or `.tar.gz` (any size) with upload progress, then the list of images Docker loaded.
- Volumes: each volume has a page (the new "Files and backup" row action) with a file browser (read-only, download files and folders), Backup (download the whole volume as `<volume>-<date>.tar`, any size) and Restore (upload a `.tar` or `.tar.gz`, optionally empty the volume first with a typed confirmation, lists the containers that use the volume and offers to stop the running ones during the restore and start them again).
- Volumes use a short-lived helper container (`busybox:1.37`, or any local `busybox:*`; asked and pulled with your consent when missing), with no network, labelled `io.ervisio.helper=volume`, `AutoRemove` and a `sleep` that bounds its life. Helpers are removed when you close the browser, after a restore, before a volume is deleted, and leftovers are swept when the Volumes pages open. Helpers are hidden from the containers list.
- Manifest: `GET images/get`, `POST images/load` and `maxUpload` (1 TiB, the maximum).
