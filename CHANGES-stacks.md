# Changes from the stacks branch (feat/stacks)

- Stacks: the .env tab is now an "Environment variables" editor. A table of names and values (add, remove, move up and down), values of names with PASS, SECRET, TOKEN or KEY hidden until revealed, and an "Advanced mode" switch for the raw text. It reads and writes the same `.env` file as before, follows the quoting rules of Docker Compose, and changes only the lines you touch (comments and formatting stay).
- Stacks: import variables by pasting a .env file or choosing one, with a preview of how many are new, replaced or kept.
- Stacks: .env checks for invalid names, duplicates, quotes that never close and text after a closing quote. Hints list `${VARIABLES}` that compose.yaml uses but .env does not set (click to add one), and variables that compose.yaml does not use.
- Stacks: the Diff tab now also compares .env with the one from the last deploy (secret values are hidden, a changed secret still shows as a changed line). A deploy saves a copy as `.compose.deployed.env`. The change count includes .env.
- Stacks: the same editor is used when you create a new stack. Templates write their .env with the same quoting, and the template page shows the .env it will write.
- Templates: custom templates. Make one from scratch (title, description, logo address, categories, compose text or container settings, variables with label, default, description and choices), from a stack ("Save as template" in the stack menu) or from a container ("Save as template" on its page). Edit, duplicate, delete, export to JSON and import (a file made here or any Portainer v2/v3 list). They show under the new "Custom" filter and in "Your templates", and install through the normal template flow.
- Templates: custom templates are shared. Each is a Portainer v3 file in `/opt/stacks/.templates/<name>.json`, so everyone who uses Docker on the machine sees them (the page says so). Variables can have a fixed list of choices, shown as a drop-down; Portainer templates that use `select` now get one too.
- Settings: new Settings page with "Export settings" and "Import settings". One versioned JSON file holds saved registries (the passwords can be left out, with a warning when they are kept), custom templates, template sources, alert rules, auto-update settings and preferences. An import shows how many items are new, replaced or unchanged before it writes anything, and never deletes.
- Fix: the "Last deploy" card no longer says "Deployed in 56,734 years".
